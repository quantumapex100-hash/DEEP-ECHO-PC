Its current protected-file manifest comparison confirms all other app JS, CSS, HTML, main/preload, playback, Search/Next preparation, lyrics sync, downloads, Smart Autoplay and theme visualizers are unchanged. Backup: `../../backups/before-calm-90fps-20261021/`.

## Implementation

- Replaced the scene's previous ~30 FPS gate with display-synchronised rendering capped at 90 scene submissions per second. On a 60 Hz display the scheduler follows 60 Hz. This is a target/cap, not a universal hardware guarantee.
- Draw the meadow with one WebGL instanced ribbon draw rather than thousands of Canvas paths. Retain the established grass count, wind, spring offsets, night illumination and flowers. The shared quadratic mesh approximates the original blade curves; shader colour/highlight and hardware antialiasing retain the meadow's appearance.
- Keep separate background, GPU grass and transparent foreground layers. Reuse the slowly changing sky pixels between ~30 Hz background updates; grass and notes use the faster loop. This prevents the expensive sky curtains from being submitted at 90 Hz.
- Bound initial layer pixel bandwidth to 1.1 million pixels and DPR 1.25. Observe actual scene cadence in 2.2 second windows and adjust render scale between 70% and 100%. Changing resolution preserves blade objects/physics and music state. Stable 60 Hz does not trigger a downgrade merely for missing 90 Hz, and quality can recover when load clears.
- Keep the earliest unconsumed pointer position across a burst for swept brush contact. Paused previews remain event-driven, coalesced, and use elapsed time rather than assuming 30 Hz.
- Bake each trail's five flecks into its fading glow texture. Reuse private GL attributes/buffers instead of reconfiguring vertex state each frame.
- Retain the Canvas renderer when WebGL/instancing is unavailable or a context is lost. Recreate shaders/buffers on restoration; explicitly hide obsolete layers. Resize uses the base canvas transform rather than whichever drawing context was last used.

## Validation

546 tests passed plus renderer integration smoke. Added GPU/fallback lifecycle, context loss/restoration, 60/90/120/144 Hz scheduling, adaptive bandwidth, and 60 Hz quality-recovery coverage. Existing controls, lyrics clock, stale lyrics, music-driven notes, trail field and exit cancellation checks pass on both renderer paths.

Native Electron tests use an isolated profile, real decoded local PCM audio through the existing player, scripted native mouse movement over grass, and hardware accelerated composition. GPU identity reported by Electron: active Intel Graphics device 0xA7AB through ANGLE/D3D11. This is not a UHD 620 validation. Search/network/extractor timing is controlled, not benchmarked.

Repeated day/night runs with hardware antialiasing produced roughly 82-89 scene submissions/second on this machine. Latest source verification: day 82 and night 85 scene submissions/second; neither phase had >50 ms renderer RAF gaps or JS long tasks. These are CPU-side scene redraw counts aligned to RAF, not externally measured display-presented frames. Each sample is 2.4 seconds, so they do not establish sustained performance on every PC. 60 Hz displays can present at most 60 distinct frames/second.
