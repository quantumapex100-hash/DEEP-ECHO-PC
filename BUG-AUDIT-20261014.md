# DeepEcho PC bug and playback audit — 14 October 2026

Updated the current 2.6.6 development source. No release, installer build or publication was performed.

## Fixed reproducible races

- A new remote or local selection now releases unrelated speculative Audio buffers. The selected prepared URL can keep buffering until actual playback starts; then its speculative buffer is released. This reduces competing transfers without discarding the selected song's preparation.
- Next lookahead rechecks pause, ended state and audio quality after asynchronous resolution. A response received after these changes cannot populate the prepared cache or start media buffering.
- Search warmup rechecks playback ownership, loading state and audio quality after resolution. Cached hover also stops while selected playback is loading. Stale background results cannot replace current preparation or repopulate a cache cleared for a new quality.
- A pending Home collection Play cannot override a later explicit song selection or Next/Previous intent. Its results can still appear in the collection drawer.
- A stale analyser-resume completion cannot start the old playback UI/visualizer ticker or add the old song to recent history after a new selection.

Existing integration coverage exercises Home/Search, rapid selections and ten Next taps, Previous, manual queue ordering, local bypass, hidden autoplay, stale search and lyric responses, downloads, theme switches and failure UI. JavaScript syntax checks passed.

Full suite uses local HTTP fixtures and temporary download files; sandboxed runs blocked these operations. The successful final run was outside the sandbox. Earlier dependency loading timed out in a child fixture; the final fixture completed within its existing timeout.

Main process (including download code), preload, Exact Lyrics, captions, lyrics timeline and Smart Autoplay file hashes are unchanged against this audit's baseline. Renderer lyrics matching/timing/sync algorithms were not changed. The renderer's playback completion guard is intentional; its historical visualizer assertion now allows and requires that guard.

No live YouTube latency benchmark or installed-profile test was run for this audit. Fresh uncached extraction/CDN delays remain; automated success does not establish that every song is instant or that every possible app bug is eliminated.
